# 007学英语

> 一个单文件的 AI 英语分级阅读器。双击 HTML 就能用，不需要服务器、不需要安装。

按你的水平生成英语短文，点任意单词即时查释义，读完自动出题——答得好下次自动升难度。查过的生词会被织进后续文章里反复遇见，配合间隔复习，让单词在真实语境中记住，而不是背单词表。

所有数据存在你自己的浏览器里，不上传任何服务器。AI 能力可接入 **9 家主流模型服务商**——DeepSeek、Kimi、智谱 GLM、通义千问、硅基流动、OpenRouter、Claude、OpenAI、Gemini——填哪家的 Key 就用哪家，随时切换。

## 功能

**阅读**

- **找真实文章（主操作）** —— 输入主题或点话题卡，联网找一篇真实存在的英文文章，带**可点开核对的原文链接**。出处取自 OpenRouter 返回的 `annotations`（搜索引擎实际访问过的页面），**不采信模型自报的网址**；拿不到任何搜索引用就整篇拒收（需 OpenRouter）
- **AI 现写（备选）** —— 找不到合适的真实文章、或只想练语言时用。内容是编的，文章头部标琥珀色「AI 现写」，不要当事实引用
- **10 个话题分类** —— 科技／AI／运动／科学／太空／商业／健康／自然／文化／创作素材，共 180 个起手话题，「换一批」在当前分类内随机
- **五档难度** —— A2 入门（初中）/ B1 基础（高中·四级）/ B2 进阶（六级）/ C1 高级（考研·雅思）/ C2 挑战（外刊原版），150–300 词
- **导入自己的材料** —— 粘贴文本、上传文件（`.txt` / `.md` / `.docx`）、或给一个网址让 AI 抓取正文
- **长文档自动分章** —— 整本书导进来会按段落切成每章约 350 词，带进度条和「上一章／下一章」。查词、译文、小测始终只针对当前这一章，所以文档再长也不影响效果；单篇上限约 150 万字符（约 25 万词）
- **多标签页** —— 最多同时开 6 篇，列在左侧栏「打开的文章」里随时切换，关掉浏览器也不丢

**查询**

- **点词查释义** —— 音标、词性、多条释义、例句；结合上下文给出该词在**当前句子**里的准确含义
- **中英互查** —— 输入中文词也能查英文对应说法，带用法与语气说明
- **整句解析** —— 拆出主谓宾等成分，点明从句类型、时态、固定搭配
- **划词翻译** —— 选中任意句子或段落即时翻译
- **全文对照** —— 一键生成逐段中文译文，与原文对照阅读
- **追问对话** —— 对某个单词继续提问，回答里出现的好词可直接收藏

**记忆**

- **生词本** —— 一键收藏，支持导出／导入 Markdown
- **间隔复习** —— 答对则间隔翻 2.5 倍（1 天 → 2.5 天 → 6 天…最长 60 天），答错则 12 小时后重来
- **生词织入** —— 生成新文章时，自动挑选最该复习的生词自然融入正文，并记录你与它的相遇次数
- **读后小测** —— 3 道单选题，优先考察你查过的词；全对自动升一档难度，答对不足 2 题自动降档

**朗读**

- **全文朗读** —— 逐句高亮跟随，自动滚动
- **跟读模式** —— 一句一停等你复述，可切慢速重播
- **语音可选** —— 自动优先选择设备上音质最好的英语语音，语速可调

**其他**

- **学习统计** —— 连续学习天数、每日文章／小测／复习次数
- **独立设置页** —— 侧栏「设置」进入，分外观／朗读／模型服务／数据四组，每组附一句说明（原来挤在一个浮层里）
- **外观** —— 纸白／米黄／豆绿／夜间四套配色，衬线与无衬线正文字体，五档字号
- **左侧栏导航** —— 阅读／生词本／复习／统计常驻左侧；窄屏（≤1000px）自动收成抽屉，顶栏出现汉堡按钮
- **选题提炼** —— 从文章内容提炼短视频选题（给内容创作者用）

## 快速开始

### 1. 拿到应用

```bash
git clone https://github.com/faqiang007/dian-du-english.git
```

或直接下载仓库里的 `dian-du-openrouter.html` 单个文件。

### 2. 用 Chrome 打开

双击 `dian-du-openrouter.html`。

> ⚠️ **不要用 Safari。** Safari 禁止本地文件页面使用 localStorage，生词本会存不住，而且不会报错。

### 3. 选服务商、填 API Key

首次打开会看到设置页：

1. **选一家服务商**。国内用户建议选带「免代理」标记的（DeepSeek、Kimi、智谱、通义、硅基流动），可以直接连，不用翻墙。
2. **去它的官网注册并创建 API Key**，粘贴进来。
3. **选模型**（可留空用默认）。填好 Key 后点 **「获取可用模型」**，会实时拉取该服务商当前所有可用模型，点一下就能选中——不用去翻文档记模型名。

Key 只存在你的浏览器里，只会发给你选的那家服务商。**每家的 Key 分开保存**，切换服务商时不用重新填。

#### 支持的服务商

| 服务商 | 国内直连 | 说明 |
|---|:---:|---|
| DeepSeek | ✅ | 便宜，日常推荐 |
| 月之暗面 Kimi | ✅ | 中文语感好 |
| 智谱 GLM | ✅ | 无模型列表接口，模型名需手填 |
| 阿里通义千问 | ✅ | 阿里云百炼平台 |
| 硅基流动 | ✅ | 聚合开源模型，注册送额度 |
| OpenRouter | 需代理 | 一把 Key 调几十家，**唯一支持网页导入** |
| Anthropic Claude | 需代理 | 需家宽 IP，机房 IP 会 403 |
| OpenAI | 需代理 | 需家宽 IP，机房 IP 会 403 |
| Google Gemini | 需代理 | 有免费额度 |

**成本参考**（以 DeepSeek 计）：生成一篇 200 词文章约 0.0035 元，查一个词约 0.002 元。日常使用一个月通常不到几块钱。

## 开发

### 环境

```bash
npm install
```

### 构建

改完源码后：

```bash
npm run build
```

macOS 用户也可以直接双击 **`构建.command`**。

构建约 130ms，产出单文件 `dian-du-openrouter.html`（约 766KB，React、图标、docx 解析库全部内联）。构建是可复现的——同一份源码重新构建，产物字节一致。

改动后回到浏览器按 `Cmd + Shift + R` 强制刷新。

### 项目结构

```
dian-du-openrouter-source.jsx   源码，所有界面和功能都在这里
main.jsx                        打包入口
template.html                   HTML 骨架（改标题、背景色时动）
build.mjs                       构建脚本
构建.command                     双击即可重新打包（macOS）
dian-du-openrouter.html         构建产物，别手改
诊断.html                        连接排查工具，可选任一服务商实际发一次请求
切换模型.html                     快速切换服务商与模型（应用外的急救入口）
```

### 回退

```bash
git log --oneline
git checkout <commit> -- dian-du-openrouter-source.jsx
npm run build
```

每次构建也会自动把上一版产物存为 `dian-du-openrouter.html.bak`。

## 数据与隐私

所有数据存在浏览器 localStorage，**不经过任何第三方服务器**（除了你主动发起的、发往你所选服务商的请求）。

| 键名 | 内容 |
|---|---|
| `dd-vocab-v1` | 生词本 |
| `dd-tabs-v1` | 打开的文章标签页 |
| `dd-stats-v1` | 学习统计 |
| `dd-prefs-v1` | 外观与语音偏好 |
| `dd-provider` | 当前选中的服务商 |
| `dd-keys-v1` | 各服务商的 API Key（`{服务商id: key}`） |
| `dd-models-v1` | 各服务商所用模型（`{服务商id: 模型名}`） |
| `dd-or-key` / `dd-or-model` | 旧版单一 Key／模型，仅用于自动迁移 |

> 改版时**不要改这些键名**，否则用户数据会「消失」。

**备份**：清除浏览器数据会连生词本一起清掉。生词本页有「复制为 Markdown」导出，应用也能反向解析导入——这是唯一的备份与换设备通道。

## 已知限制

- **数据不跨设备同步。** localStorage 属于单个浏览器，换设备＝空的生词本。这是设计上的取舍：无服务器、无账号、零成本、完全私密。
- **必须用 Chrome 或 Edge。** Safari 不支持本地文件页面的 localStorage。
- **导入网页目前只有 OpenRouter 支持。** 它依赖服务商提供的联网搜索工具，各家写法不统一，暂时只接了 OpenRouter。用别家时会提示改用「粘贴文本」导入——抓不到时这也是最稳的办法。
- **AI 生成的文章不是真实报道。** 文章头部会标「AI 现写」琥珀色徽章加以区分；「真实来源」是绿色徽章并附原文链接。想要有出处的内容请用「来篇真实报道」或网址导入。
- **朗读音质取决于设备。** 用的是浏览器内置语音合成，苹果设备和 Windows + Edge 效果最好。
- **单篇文档上限约 150 万字符。** 浏览器 localStorage 实测约 480 万字符封顶，且要和生词本、统计共用，所以给单篇留 150 万（约两本长篇小说）。超了会在导入时明确拦下，不会静默截断。真要放几十 MB 得换成 IndexedDB 存储，那是另一档改动。

## 疑难排查

### 报「连不上 XX 服务器」但网络正常

代码把 `fetch` 的所有异常都归到网络错误分支，所以**请求在发出前就失败**时也会显示这条。最常见的原因是给请求头设了非 ASCII 的值：

```js
// ✗ 浏览器会抛 TypeError: String contains non ISO-8859-1 code point
headers: { "X-Title": "007学英语" }

// ✓
headers: { "X-Title": "007 English Reader" }
```

**加任何请求头都只能用 ASCII 字符。**

### OpenAI / Anthropic 的模型返回 403

报错原文：

```
The request is prohibited due to a violation of provider Terms Of Service
```

这不是 Key 无效也不是余额不足，而是你的出口 IP 是**机房 IP**，被模型提供方判定为代理而拒绝。DeepSeek 不做这种拦截，所以往往表现为「只有 DeepSeek 能用」。

查自己的出口 IP 类型：

```bash
curl "http://ip-api.com/json/?fields=hosting,country,isp"
```

`hosting: true` 是机房 IP（会被拦），`false` 是住宅 IP（能过）。要用 Claude 或 GPT，需要切换到「原生 / 家宽 / 住宅 IP」节点。

### 提示「出了点问题」但看不出原因

不同服务商的报错方式不统一，比如 **Google Gemini 会把「密钥无效」报成 400** 而不是 401。代码已针对错误消息文本做了识别，但仍可能有漏网的。

### 想换个模型但不知道该填什么

设置页填好 Key 后点 **「获取可用模型」**——列表是从服务商 API 实时拉取的，永远不会过时。

### 其他情况

用浏览器打开 `诊断.html`，选中任一服务商实际发一次请求，把 HTTP 状态码和原始返回完整显示出来，并指出解析在哪一步失败。

### 想加一家新的服务商

只要它兼容 OpenAI 的 `/chat/completions` 格式，在源码的 `PROVIDERS` 表里加一条即可，不用改其他代码。前提是它的 CORS 要放行 `file://` 的 null 来源，验证方法见源码顶部注释。

## 技术栈

| | |
|---|---|
| 界面 | React 18.3.1（无框架、无路由、无状态管理库） |
| 图标 | lucide-react |
| 文档解析 | mammoth（读 `.docx`） |
| 打包 | esbuild，单文件内联输出 |
| AI | 9 家服务商，两种协议（OpenAI 兼容 `/chat/completions` + Anthropic Messages） |
| 存储 | 浏览器 localStorage |
| 朗读 | Web Speech API |

没有构建产物之外的运行时依赖，没有后端，没有数据库。
