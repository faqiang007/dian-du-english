# 技术方案 · 复习系统

> 配套阅读：`spec-复习系统.md`（做什么）、`constitution.md`（不许碰什么）。
> 这份讲「为什么这么做」和「改动时会牵连到哪里」。

## 数据结构

生词本单条记录（存 `dd-vocab-v1`）：

```js
{
  key:     "abandon",        // 小写词形，唯一标识
  surface: "abandoned",      // 用户点的时候的原始字面
  data:    { type: "en" | "zh", word, phonetic, senses, ... },  // 词典结果
  savedAt: 1725...,          // 收藏时间戳
  meet:    3,                // 打过几次照面（收藏算 1 次）
  rv: { due: 1725..., iv: 8, streak: 2 }   // 复习进度
}
```

`iv` 单位是天，`due` 是毫秒时间戳，`streak` 是连续答对次数。

## 涉及哪几层

纯前端单层，没有后端。复习系统全部跑在浏览器里：

| 部分 | 依赖 | 说明 |
|---|---|---|
| 到期计算、间隔推进 | 无 | 纯本地算术，不联网、不花钱 |
| 生词织入选词 | 无 | 本地排序 |
| 织入结果检测 | 无 | 本地正则比对 |
| 文章生成、小测出题 | 模型 API | 唯一花钱的部分 |
| 数据落盘 | localStorage | 无事务、无并发，写入即生效 |

## 关键决策（ADR）

### ADR-1：自己写 2.5 倍固定间隔，不用 SM-2 / Anki 算法

- **选了什么**：答对 `iv × 2.5` 封顶 60 天，答错清零重来、12 小时后再见。
- **放弃了什么**：SM-2（Anki 的算法，带难度因子 E-Factor、每个词单独调整曲线）。
- **为什么**：SM-2 要求用户在作答时给出 4 档自评（完全忘了/想了很久/有点犹豫/秒答），才能算出难度因子。这一步对自学者是负担，且自评本身不准。当前方案只要「记住了 / 没记住」两个按钮，用户零思考成本，且间隔序列（1→3→8→20→50）用一句话就能解释清楚。
- **代价**：所有词共用同一条曲线，简单词和难词推进速度一样，效率不如 SM-2。接受——这个项目的核心是"在语境里重逢"，不是把间隔算法调到最优。

### ADR-2：织入成功只加 `meet`，绝不推迟 `due`

- **为什么**：在文章里读到一个词，和在复习卡上主动回忆起它，是强度完全不同的两件事。如果织入也推迟到期时间，用户会在"其实没记住"的情况下不断被推后复习，最后单词照样忘掉，而系统显示一切正常——这是最难发现的一类 bug。
- **所以**：`meet` 和 `rv` 是两套独立信号，`meet` 只用于展示（「见过 N 次」）和排序参考。**任何后续改动都不许把这两者耦合起来。**

### ADR-3：织入结果靠正则实测，不信任模型的自述

- **为什么**：模型经常在 prompt 里被要求用某些词，实际写作时悄悄省略，还在回复里声称用了。只要不实测，`meet` 计数就会虚高，用户以为自己反复见过某个词、实际一次没见。
- **怎么做**：`\b<词>[a-zA-Z]*\b` 忽略大小写。允许词尾变形（run 匹配 running/runs），不允许前缀不同的词误命中。
- **代价**：不规则变化词（go → went）检测不到，会漏记。接受，宁可少记不可多记。

### ADR-4：难度自动升降只由小测触发，点词密度只做提示

- **为什么**：小测是主动作答，是硬证据；点词密度是间接推断，可能是用户在精读、或者在查已经认识的词。硬证据可以自动改，软证据只能提示。
- **另一个原因**：难度改了要下一篇才生效。如果在用户读到一半时静默改掉，他会在下一篇突然遇到难度跳变而不知道发生了什么。所以提示必须带一个"调到 X"的按钮，让用户自己按。

### ADR-5：`rvOf()` 兜底而不是数据迁移

- **为什么**：老版本存的生词没有 `rv` 字段。可以写一段迁移代码在启动时补上，但那意味着每次改结构都要写一段一次性代码，且迁移出错会直接毁掉用户数据（无备份、无回滚）。
- **选了**：读取时用 `rvOf(v)` 返回默认值，永不改写老数据。代价是每次读都多一层函数调用，可忽略。
- **推论**：以后给生词加新字段，一律沿用这个模式——**读时兜底，不做写入式迁移**。

## 改动时的连带影响

想动某处之前，先看它牵连到哪些地方：

| 你要改的东西 | 会连带影响 |
|---|---|
| `rv` 结构或 `rvOf()` | 到期列表、复习页、生词本三分组、织入候选排序、已掌握判定、统计页待复习数 —— 几乎全部 |
| `MASTER_STREAK`（现为 3） | 「已掌握」分组、统计页数字。注意它和织入候选的 `streak < 2` 是两个独立阈值，改一个不会自动改另一个 |
| `WEAVE_MAX`（现为 6） | 选词上限提示文案里写死了数字，要一起改 |
| 织入检测正则 | `meet` 计数、文章底部「本篇织入了」提示、正文高亮 |
| 小测出题 prompt | 升降档判定依赖题目数量恰好为 3（全对才升）。改题数必须同步改判定 |
| `LEVELS` 数组增删档位 | 升降档的边界判断靠数组下标，加档位会自动生效；但删档位会让存在 `dd-stats-v1` 里的旧难度 id 失效，需要兜底 |

## 已知的粗糙处（不是 bug，是当前接受的代价）

1. **复习队列不去重同源词**。`run` 和 `running` 若分别被收藏，会当两个词各自复习。
2. **`iv` 封顶 60 天后不再增长**，已掌握的词每两个月还会回来一次。有意为之，不打算改。
3. ~~**没有"暂时跳过这个词"的操作**~~ —— 2026-09-02 已实现，规格与验证记录见 `spec-复习跳过.md`。
   顺带记录一个现有缺陷：复习途中若某个词被移出生词本，卡片上那个「跳过」按钮调的是 `onAnswer(true)`，
   会让「记住了 N 个」和当日复习次数虚高。同一份规格里一并修掉。
4. **小测依赖模型返回合法 JSON**。失败就整个小测失败，没有重试。
