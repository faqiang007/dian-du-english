# 需求说明 · 复习中跳过一个词

> 状态：**已实现并验证**（2026-09-02 定稿，同日实现）
> 前置阅读：`constitution.md`、`spec-复习系统.md`
> 这个功能小到不值得拆成三份文档，需求、方案、任务合在这一份里。

## 要解决的问题

现在复习卡片翻面后只有「😵 还不熟」和「✅ 记住了」两个出口，没有第三条路。遇到一个此刻不想判断的词，用户只能：

- 随便按一个 —— 污染复习数据，按错了这个词的间隔就歪了
- 退出复习 —— 本轮剩下的词全不做了

两个都不该是唯一选项。需要一个**不产生任何复习信号**的出口。

## 核心决策：跳过 = 什么都没发生

跳过一个词，系统对这个词的认知**不应该发生任何变化**——既不是"记住了"，也不是"没记住"，而是"这次没问"。

所以跳过**绝不修改** `rv`（`due`／`iv`／`streak` 全部不动），也不动 `meet`。这是 `spec-复习系统.md` 里 ADR-2 那条原则的延续：弱信号不许污染复习进度。

**直接后果，必须让用户看见**：`due` 没变，所以跳过的词仍然是「到期」状态，侧栏红色数字不会减少，用户马上再点一次复习还会遇到它。这不是 bug，但界面不说清楚就会被当成"没保存"。

## 需求（EARS 单句）

**1** 当复习卡片处于正面（还没翻开看释义）且该词仍在生词本中时，系统应该在翻面按钮下方显示一个**弱化样式**的「跳过」按钮。
> 弱化是必须的：它不能跟「点开看释义」抢注意力，跳过应该是偶尔用的逃生口，不是常规操作。

**2** 当复习卡片已经翻面时，系统**不应该**显示跳过按钮。
> 都看到答案了再跳过没有意义，此时该给的是「记住了／还不熟」的判断。留着这个出口只会让用户逃避判断，复习质量反而下降。

**3** 当用户点击跳过时，系统应该前进到队列的下一张卡，且**不修改该词的任何字段**（`rv`、`meet` 都不动）。

**4** 当用户点击跳过时，系统**不应该**给当日复习次数统计加 1，也不应该计入本轮的「记住了」或「还不熟」任何一个。

**5** 当用户跳过一个词时，系统应该把本轮的跳过计数加 1。

**6** 当本轮结束且跳过数大于 0 时，完成页应该在原有的「记住了 X 个 · 还不熟 Y 个」之后，显示「跳过 Z 个」，并附一句说明：这几个词仍在待复习里，随时可以再来。
> 这句说明是**必需的**，不是可选的润色——它解释了为什么侧栏数字没减少。

**7** 当本轮所有卡片都被跳过（记住 0 个、还不熟 0 个、跳过大于 0）时，完成页**不应该**显示 🎉 和「今日复习完成！」，而应该显示中性文案（例：「这轮都跳过了，它们还在等你」）。
> 什么都没做却被恭喜，是很扫兴的假反馈。

**8** 当复习途中某个词已被移出生词本时，系统应该继续显示「这个词刚被移除了」和跳过按钮，且该按钮走跳过逻辑。
> **这是在修一个现有缺陷。** 当前这个按钮调的是 `onAnswer(true)`，等于按「记住了」处理：会让完成页的「记住了 N 个」虚高、当日复习次数多记一笔，而那个词其实已经不在生词本里了。

**9** 当用户跳过若干词并完成本轮后回到首页时，侧栏和首页的到期数应该仍然包含这些被跳过的词，用户可以立即再次进入复习并再次遇到它们。

## 明确不做

- **不加键盘快捷键。** 总则第七条：需要解释才知道的交互就不做。
- **不做「这个词别再问我了」**（暂停／归档）。那是另一个需求，语义完全不同——跳过是"这次不问"，归档是"以后都不问"。真需要的话单独写一份规格。
- **不限制跳过次数。** 队列只减不增，不可能循环，没有必要加限制。
- **不把跳过计入学习统计。** 跳过不是学习行为。

## 技术方案

改动集中在两处，不涉及数据结构变更，因此**没有兼容旧数据的问题**。

| 位置 | 改动 |
|---|---|
| `rev` 状态（源码 ~2344） | 加一个 `sk: 0` 计数。它只活在内存里，不落盘，退出复习即消失 |
| `skipReview()`（新增，紧邻 `answerReview`） | 只做 `i + 1` 和 `sk + 1`，**不调 `setVocab`、不调 `bumpStat`** |
| `ReviewView`（源码 3947） | 加 `onSkip` prop；正面分支加按钮；「词被移除」分支改调 `onSkip`；完成页加文案分支 |

为什么 `skipReview` 要单独写一个函数、而不是给 `answerReview` 加个参数：`answerReview` 的每一行都在写数据（改 vocab、记统计、累加对错），跳过则是一行数据都不写。塞进同一个函数会让它变成一堆 if，以后很容易在改动时手滑让跳过写进数据——分开写，物理上就不可能出这个错。

## 任务分解

按顺序做，每步都能单独验证。

**T1 · 给复习状态加跳过计数**
在 `startReview()` 里把 `sk: 0` 加进 `setRev({...})` 的初始值。
✅ 完成标志：进入复习后 `rev.sk` 为 0，不影响现有任何行为。

**T2 · 写 `skipReview()`**
新增函数，只更新 `rev`：`i + 1`、`sk + 1`、`flip` 复位为 false。不碰 vocab、不碰统计。
✅ 完成标志：对应需求 3、4、5。

**T3 · 正面加跳过按钮**
`ReviewView` 接 `onSkip`，在未翻面分支的「点开看释义」按钮下方加弱化按钮。翻面分支不加。
✅ 完成标志：对应需求 1、2。翻面后按钮消失。

**T4 · 修「词被移除」分支**
把那里的 `onAnswer(true)` 改成 `onSkip`。
✅ 完成标志：对应需求 8。复习途中删掉一个词，跳过后完成页的「记住了」计数不再虚增。

**T5 · 完成页文案**
跳过数大于 0 时追加「跳过 Z 个」和那句说明；全跳过时换成中性文案和非庆祝 emoji。
✅ 完成标志：对应需求 6、7。

**T6 · 样式**
跳过按钮沿用已有的弱化按钮样式（`btn-soft` 或同级），不新造视觉。四套配色下都要能看清但不抢眼。

**T7 · 构建与手测**
`npm run build`，Chrome 里 `Cmd+Shift+R` 强刷，逐条走：
1. 翻面前有跳过、翻面后没有
2. 跳过后该词的 `due` 没变（复习完回首页，到期数不减少）
3. 完成页跳过计数正确，且有那句说明
4. 全部跳过时不显示 🎉
5. 复习途中在别的标签页删掉一个词，走到它时跳过，计数不虚增
6. 当日复习次数统计没有因跳过而增加

### 关于需求 8：那段是不可达的防御代码

想触发它，需要「复习队列已生成、但该词已不在生词本」这个状态。实测走不到：

- 进复习的四个入口全都调用 `startReview()`，每次重新快照队列
- 复习页本身没有删词入口
- 用顶部搜索框查词再取消收藏可以删词，但**查词会自动把视图切回阅读页**（词典只在阅读页显示），复习会话就断了

所以这段代码从来没有执行过——这正是那个 `onAnswer(true)` 的缺陷能长期潜伏的原因。
改动本身是对的（`onClick={onSkip}`，React 传进来的事件对象对无参数的 `skipReview` 无害），
但它的正确性目前只有代码审查背书，没有运行时证据。

**如果以后要让这段代码真正可达**，需要先给复习页加一个删词入口，或者让查词不再强制切视图。
在那之前，不要把它当成经过验证的路径。

### 一个排查用的知识

构建产物里的中文全部被 esbuild 转成了 `\uXXXX` **大写**转义。
所以 `grep "今日复习完成" dian-du-openrouter.html` 永远是 0 个命中，不代表文案丢了。
要在产物里找中文，先把字符串转成大写转义形式再搜。
