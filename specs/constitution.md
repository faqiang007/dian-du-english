# 007学英语 · 项目总则

> 整个项目从头到尾都要遵守的硬规矩。改任何代码前先读这份。
> 每次开新对话，把这份文件的路径丢给 AI，不用再口头交代背景。
> 最后更新：2026-11-14（复习带原句、每日改三格并按「做了」算、完整备份）

## 这个项目是什么

一个**单文件**的 AI 英语分级阅读器。用户双击 `dian-du-openrouter.html` 用 Chrome 打开就能用，没有服务器、没有账号、没有安装步骤。所有数据存在用户自己浏览器的 localStorage 里。

设计上的根本取舍：**用"数据不跨设备"换"零成本、零依赖、完全私密"**。任何提议引入后端、账号体系、云同步的改动，都是在推翻这个取舍，必须先跟项目所有者确认，不能顺手就加。

## 一、数据安全（最高优先级）

- **禁止改动已有的 localStorage 键名。** 改一个键名，用户的生词本就会静默"消失"，且没有任何报错。现有键名清单（共 14 个，绝大部分定义在 `src/lib/storage.js` 顶部）：

  | 键名 | 内容 |
  |---|---|
  | `dd-vocab-v1` | 生词本（核心资产，丢了最痛） |
  | `dd-tabs-v1` | 打开的文章标签页 |
  | `dd-article-v1` | 当前正在读的文章 |
  | `dd-history-v1` | 读过的文章归档 |
  | `dd-stats-v1` | 学习统计 |
  | `dd-seen-v1` | 每个词查过几次（跨会话累计） |
  | `dd-dict-cache-v1` | 词级查询缓存 |
  | `dd-book-cache-v1` | 导入书籍正文缓存 |
  | `dd-lib-v1` | 教材清单缓存 |
  | `dd-prefs-v1` | 外观与语音偏好 |
  | `dd-provider` | 当前选中的服务商 |
  | `dd-keys-v1` | 各服务商的 API Key |
  | `dd-models-v1` | 各服务商所用模型 |
  | `dd-or-key` / `dd-or-model` | 旧版单一 Key／模型，仅用于自动迁移，不许删 |

- **要改数据结构时，只能往里加字段，不能改已有字段的含义。** 读旧数据必须有兜底（例：`rvOf(v)` 给没有 `rv` 字段的老词返回默认值，把它当成"到期"）。
- **API Key 只发给用户选中的那家服务商**，不许发往任何其他地址，不许打日志，不许进入任何统计。
- 用户数据不许上传到任何第三方服务器。唯一的网络请求是用户主动发起的模型调用，和教材语料的 jsDelivr 拉取。

## 二、运行环境

- **目标浏览器是 Chrome / Edge，通过 `file://` 直接打开。** 不许依赖任何需要 HTTP 服务器才能工作的特性（模块 import、Service Worker、部分 fetch 场景）。
- Safari 在 `file://` 下禁用 localStorage 且不报错，所以**不支持 Safari**，也不必为它做兼容。
- **所有 HTTP 请求头的值只能是 ASCII 字符。** 写入非 ASCII（例如中文的 `X-Title: "007学英语"`）浏览器会在请求发出前抛 `TypeError`，而代码把 fetch 的所有异常都归到"网络错误"分支，表现为"连不上服务器"，极难排查。
- 教材语料走 `https://cdn.jsdelivr.net/gh/faqiang007/dian-du-english@main/教材/...`。选它是因为它同时满足两个条件：国内直连可达、且返回 `access-control-allow-origin: *`。换任何其他源前必须先验证这两点。

## 三、构建与产物

- 源码全在 `src/` 文件夹里（结构见 README 的「项目结构」）。**`dian-du-openrouter.html` 是构建产物，任何情况下都不许手改。**
- 改完源码必须执行 `npm run build`（或双击 `构建.command`）重新打包，否则用户打开的还是旧版本。
- 构建必须保持可复现：同一份源码重新构建，产物字节一致。
- 不许引入需要运行时联网加载的依赖（CDN 里的 JS 库等）。所有依赖必须能被 esbuild 内联进单文件。

## 四、代码风格

- **变量名、函数名、注释一律用中文写清意图**，面向的是非科班背景、隔几周回头看的维护者。
- 关键决策要在代码里留一句"为什么"，不只写"是什么"。例：阈值为什么取 8% 而不是 5%。
- 界面文案说人话，不出现技术术语（不说"localStorage 已清空"，说"生词本已清空"）。
- 新增模型服务商时，只在 `src/data/providers.js` 的 `PROVIDERS` 表里加一条，不许改动其他代码。前提是该服务商兼容 OpenAI 的 `/chat/completions` 格式，且 CORS 放行 `file://` 的 null 来源。

## 五、AI 生成内容的诚实性

- AI 现写的文章必须在头部标注琥珀色「AI 现写」徽章，不许伪装成真实报道。
- 「找真实文章」的出处只采信搜索引擎实际访问过的页面（OpenRouter 返回的 `annotations`），**不许采信模型自报的网址**。拿不到任何搜索引用就整篇拒收。
- 生成文章的 prompt 必须要求：只写科学共识与教科书级常识，不编造具体数字、年份、人名、研究结论；有争议的话题要如实写明有争议。

## 六、内容完整性

- 长文档按段落切章时，**一个篇目必须是一个完整单元**（一则寓言、一篇童话、一整章）。超长的整篇丢弃，绝不切碎成"第 9 段之 4"这种前不着村后不着店的东西。
- 超出容量上限时必须在导入环节明确拦下并告知用户，**绝不静默截断**。单篇上限约 150 万字符。

## 七、界面克制

- 需要解释才看得懂的控件就该删掉，而不是加说明文字。
- 解释性文字一律折叠，第一屏不堆字。
- 自动调整用户设置（如难度）时必须让用户知情，不许静默改动。只在有充分证据时才自动调，证据不足就"提示"而不是"改"。

## 八、界面和逻辑分开放

- **`src/store.js` 是大脑，`src/views/` 是脸。** 状态、网络请求、提示词、缓存、复习算法只写在 store 里；界面文件只负责画，和把点击转给 store。改外观不许动 store，改功能尽量不动界面。
- store 里每个请求计数器（`xxxReqRef`）、每次 `resetReadingContext()` 都对应一个修过的 bug（慢请求盖掉新结果、换文章后旧译文写回来之类）。改之前先读懂它在防什么，不许为了"整洁"删掉。
- **颜色、字体、圆角只在 `src/styles/tokens.css` 里定义**，别的样式文件一律用变量，不写死色值。四套配色的名字（paper / cream / green / dark）存在用户偏好里，不许改名。
- **红变黑，就是学会了。** 朱红只表示"还在学"——没写的格子、没记牢的词、答错的题；墨黑表示"已经会"——写过的格子、掌握的词，以及所有主按钮。不许拿红色去做别的装饰，否则这句话就不成立了。琥珀色只留给「AI 现写」徽章和提醒条，绿色只留给「真实来源」（见第五条）。
- **「今日三格」（温、读、测）不另存数据**，全是从学习统计的 `log` 里现算的（`src/lib/day.js`）：`r` 复习、`rd` 当天把到期词温完过、`a` 新开一篇、`c` 接着读或重读、`w` 读到章末的词数、`q` 小测、`t` 对话里用户自己说的句数。`c`、`rd`、`w` 是 2026-11 新加的字段，老数据里没有，读的时候一律按 0 处理。
- **格子按「做了」算，不按「碰过」算**（2026-11-14 起，`STRICT_FROM`）：温＝到期的温完或温满 10 个，读＝有一章读到了章末，测＝做完一次小测。同一天起「说」不再算每日的格子（项目所有者定的：这个应用练词汇量和阅读理解，开口先不做），「说」那一页保留。这天之前的日子仍按老规矩算（四格、碰过就算），不许拿新标准回头改写足迹。
- **完整备份只装学习数据**（`BACKUP_KEYS`，见 `src/lib/storage.js`）：不装 API Key，不装各种缓存。恢复是整份覆盖，必须先让用户看到会盖掉什么、确认了才动；写到一半失败要退回原样。
- 生词条目上的 `sent`（遇见它的那句原文）、`from`（出自哪篇）是 2026-11 新加的字段，老词没有，一律当空处理。
- 全站只有三种按钮（`.btn.pri` / `.btn.sec` / `.btn.txt`）、一种标签（`.tag`）、一种提示条（`.callout`）。要新样式之前先看 `base.css` 里有没有现成的。
